# claude_design.md — бриф для Claude: визуальная презентация к защите ВКР

Этот файл — инструкция, **как и что описать Claude**, чтобы он собрал визуальную презентацию к
защите магистерской диссертации *JointAdaSpec*. Содержание слайдов и дословный текст доклада уже
есть в [`papers/pres.md`](pres.md) — здесь к ним добавлены дизайн-система, правила оформления и
**готовый мастер-промпт** (раздел 7), который достаточно скопировать в Claude.

---

## 1. Назначение и как пользоваться

1. Откройте новый чат с Claude (claude.ai), модель — Sonnet 4.6 или Opus.
2. **Прикрепите изображения** (раздел 5): нужные PNG из `reports/thesis_figs/png_slides/` и
   `papers/repo_qr.png`. Если прикрепить нельзя — Claude построит схемы сам и оставит для фигур
   подписанные плейсхолдеры.
3. Скопируйте **мастер-промпт из раздела 7** и при желании допишите 1–2 уточнения (вуз, ФИО
   руководителя, предпочитаемый формат вывода).
4. Получите деков, проверьте по чек-листу (раздел 9), при необходимости попросите Claude
   доработать отдельные слайды.

Источник истины по содержанию и числам — `pres.md` (там же короткая канва речи на 5–5,5 минут). Этот файл
задаёт **визуальную форму**, не переписывая содержание.

## 2. Контекст и аудитория

- **Тема.** Оптимизация больших языковых моделей методом адаптивного спекулятивного декодирования
  (метод JointAdaSpec на основе MDP).
- **Жанр.** Защита магистерской ВКР; аудитория — государственная экзаменационная комиссия.
- **Язык.** Русский (термины вводить как «рус. (english, АББР)» при первом упоминании).
- **Объём.** 14 слайдов, формат 16:9, регламент свободного доклада ~5–5,5 минут.
- **Тон.** Академический, но визуально чистый и современный: минимум текста, крупные акценты,
  один смысловой посыл на слайд. Это научный доклад, а не маркетинговый питч.

## 3. Дизайн-система

**Палитра.**
- Заголовки / плашки: тёмно-индиго `#1B2A4A`.
- Фон: белый `#FFFFFF` (допустим очень светлый `#F7F8FA`).
- Основной текст: графит `#1F2430`.
- Акцент (выделить JointAdaSpec, активные элементы): бирюзовый `#2BB3A3`.
- **Семантические цвета (важно для честности):** зелёный `#1E9E5A` — только для статистически
  значимых положительных результатов (p < 0,05); нейтральный серый `#8A8F98` или приглушённый
  янтарь `#B5852A` — для честных оговорок, ничьих и нулевых результатов. Не красить нулевой
  результат красным как «провал» и значимый — ярко-зелёным как «победа над всеми».

**Типографика.**
- Заголовки: гротеск с кириллицей — Inter / Manrope / Montserrat, **Bold**, 36–40 pt.
- Текст и буллеты: тот же гротеск, Regular/Medium, 22–26 pt (минимум 24 pt для читаемости из зала).
- Код и формулы-фолбэк: моноширинный JetBrains Mono / Fira Code.
- Подписи к рисункам/таблицам: 16–18 pt, цвет `#5A6172`.
- Big-number callout: 60–96 pt (крупная цифра результата).

**Сетка и раскладки.** 12 колонок, поля ~6 % по краям, безопасная зона снизу под номер слайда и
(опц.) логотип вуза. Базовые мастер-раскладки:
1. **Титул** — центрированный текст.
2. **Проблема/секция** — крупный тезис сверху + 3–4 коротких буллета.
3. **Две колонки** — текст слева | рисунок справа (или наоборот).
4. **Big-number** — 1–2 крупные цифры + краткий контекст.
5. **Таблица результатов** — «зебра», выделить строку `jointadaspec` акцентом.
6. **Матрица/таксономия 3×3** — выделить пустую клетку.
7. **Карточки теорем** — список A/B/C/D/2.3/2.4 плитками.
8. **Закрывающий + QR** — крупный QR + URL.

**Графика.** Тонкие линейные иконки одного набора (например Lucide), без цветного клипарта и
фотостоков. Единый стиль рамок и теней (или вовсе без теней — плоско). Анимации минимальны:
только появление по клику, без «вращений».

## 4. Глобальные правила (честность — соблюдать строго)

Эти правила важнее красоты. Нарушение = искажение результатов работы.

- **Только зафиксированные числа** из `pres.md`. Ничего не выдумывать и не округлять «в свою
  пользу».
- **Никаких «быстрее всех / побеждает всех / SOTA / превосходит все методы».** Главный нарратив —
  «единый фреймворк + теория + честная характеризация границ».
- **Прямая генерация (AR) — самый быстрый метод.** «2,22×» указывать строго с подписью
  «относительно ванильного спекулятивного декодирования», не относительно AR.
- **joint ≈ cascade — статистическая ничья** (Δ = −0,13 %, p = 0,96). Не рисовать столбик joint
  выше cascade; на Парето они рядом.
- **Пара 7B/1.5B — нулевой результат** (3 независимых окна). Показывать честно, нейтральным
  цветом, как установленную границу применимости, а не прятать.
- **Немонотонность качества** по доле принятий (+7,4 / −2,6 п.п.) — показывать обе стороны.
- Формулы — через KaTeX/MathJax или вставлять как изображения LaTeX; **не** «сырой» юникод вида
  `∏_{t=1}^{n}`.
- Один смысловой посыл на слайд; на слайде — тезисы, развёрнуто проговаривается устно (текст в
  `pres.md`).

## 8. Форматы вывода и рекомендация

- **reveal.js (один HTML) — рекомендуется.** Самодостаточно, открывается в любом браузере и с
  проектора, легко показывать со своего ноутбука; картинки можно встроить base64. Минус — правки
  руками в HTML.
- **PPTX через python-pptx.** Удобно, если на защите требуют файл PowerPoint и нужно править в
  привычном редакторе. Минус — сложнее держать единый стиль и формулы.
- **Google Slides.** Совместная правка и показ из браузера; перенос дизайна — вручную по этому
  брифу.

**Готовый конвейер сборки.** Деков уже собирается одной командой — `make slides` (или
`bash scripts/build_slides.sh`) — и выгружается в `papers/dist/` сразу в трёх форматах:
`JointAdaSpec_defense.pptx` (мастер, `python-pptx` по числам из `pres.md`), `.pdf` и
самодостаточный `.html` (LibreOffice + poppler). Содержание и числа — только зафиксированные
(см. правила честности §4). Этот раздел-бриф остаётся источником визуальных решений; ручную
пересборку через Claude/reveal.js можно использовать как альтернативу, не меняя числа.
